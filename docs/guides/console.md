# 模块化视觉控制台

控制台按现场操作组织为五个页面。导航仅改变界面显示位置，不重建视频连接、
不清空未保存的表单，也不改变原有 API、检测任务或统一分析流程。

右上角可切换「中文 / English」，浏览器会记住选择；也可通过 `?lang=zh` 或
`?lang=en` 直接打开相应语言。切换同步到已经打开的通道诊断面板，保留未保存的
设置与现有视频连接。页面标题、操作、说明、状态及事件标注随语言切换；人员姓名、
分析原文、接口地址和结构化数据保留原值。界面使用功能名称及操作说明。

| 页面 | 现有功能的位置 |
| --- | --- |
| 实时工作台 | 输入、视觉核心和输出概览；多路视频连接；逐路检测项目及敏感度；统一分析启停；各路诊断 |
| 能力与规则 | 现有视觉任务入口；所有摄像头共享的人员库 |
| 事件与回放 | 主通道事件筛选、视频证据、分页和实时结果记录 |
| 输出与集成 | 按通道选择的实际拉流、JSON、SSE、GVD1 地址及复制；原主通道输出、播放缓存和状态诊断 |
| 部署与设置 | 运行位置、服务地址、凭据、GPU 配置、采样率、视频默认值和线路测速 |

先在工作台连接视频，再展开该路「详细控制」选择任务与敏感度，最后统一开始分析。
分析期间的原有设置锁定规则继续生效；停止分析保留视频预览。
其他通道的事件记录和播放缓存继续从该路「本机摄像头 / 诊断」进入。

输出页从 `GET /v1/fleet` 的 `cameras[].outputs` 读取地址。通道切换同时更新链接与
复制内容；没有返回的接口不生成猜测地址。主通道旧接口和诊断仍明确标注作用范围。

区域规则、入侵、物品遗留、自动动作、留存策略以及业务应用集成为灰度概念占位，
控件不可点击，不表示已经实现或启用。实际 Webhook 交付继续沿用现有服务配置。

界面使用能力名称，不显示模型名称。自备服务标识保留原字段及保存协议，以密码输入框
显示；诊断 JSON 只隐藏模型标识，保留延迟、置信度、人物标识等业务数据，原 API 数据不变。

## 动态检测项目

控制台通过 `GET /v1/ui/info` 的 `event_catalog` 读取后端当前支持的事件。
各路详细设置从本路 `analysis/settings` 响应读取相同格式的目录，按该路返回值生成
选项；保存仍使用原有的 `features` 和 `event_sensitivities` 字段。
任务概览、检测复选框、敏感度、历史筛选和视频标注共用目录中的名称。
“刷新检测项目”会重新读取主通道目录和已加载通道的设置，有未保存修改的通道保留草稿。
主通道保留仍有效的选择和参数草稿；逐路设置重新
展开时读取该路目录，有未保存修改时保留草稿，可用“放弃未保存修改”重新读取。
目录不可用或版本不支持时显示错误并禁止提交相应设置，不猜测可用事件。

目录版本为 `1`，`events` 是有序数组，空数组表示没有可用事件。每项包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定的事件 ID，用于请求与结果关联 |
| `labels`、`aliases` | 中英文名称和旧名称别名；未知历史 ID 仍以文本显示 |
| `default_enabled` | 首次加载时是否默认选中 |
| `kind` | `detection` 或 `identity`，区分事件与身份展示 |
| `scope` | `person` 或 `scene`，区分人物与场景事件 |
| `sensitivity`（可选） | 默认值与选项数组；缺失时不生成敏感度控件 |

敏感度选项沿用 `value`、`label`、`description`，也支持 `labels`、`descriptions`
中的 `zh` / `en` 文案。UI 不限定选项值为 standard/high，实际合法值由后端校验。
后端适配器 `event_catalog.py` 从检测器支持列表与敏感度策略生成目录；显示名称、
范围等元数据集中在 `EVENT_PRESENTATION`。新增后端事件会自动出现，没有名称元数据
时先显示 ID。无需在 HTML、逐路控制器和标注代码中再维护事件名单。

目录只是展示契约，不会启用尚未实现的检测器。推理、事件确认、清除、追踪和归档
仍由现有流程负责；更换内部实现时保持这些公开接口的语义即可复用控制台。若新增
全新的参数类型或改变接口语义，需要扩展契约和通用控件，而非为单个事件写页面逻辑。

前端回归覆盖导航后草稿保留、通道输出关联、失联后的链接禁用、复制降级、
嵌入式诊断及显示层保密。实际推理性能与准确率不属于界面验收。
