# 模块化视觉控制台

控制台按现场操作组织为六个页面。导航仅改变界面显示位置，不重建视频连接、
不清空未保存的表单，也不改变原有 API、检测任务或统一分析流程。

右上角可切换「中文 / English」，浏览器会记住选择；也可通过 `?lang=zh` 或
`?lang=en` 直接打开相应语言。切换同步到已经打开的通道分析记录、全画面描述、任务实时判断、回放和诊断面板，保留未保存的
设置与现有视频连接。页面标题、操作、说明、状态及事件标注随语言切换；人员姓名、
分析原文、接口地址和结构化数据保留原值。界面使用功能名称及操作说明。

| 页面 | 现有功能的位置 |
| --- | --- |
| 实时工作台 | 多路视频与统一分析启停；画面旁直接展示各路全画面描述和任务实时判断；视频接入、检测任务、实时结果、播放设置、服务诊断和通道回放入口 |
| 工作流 | 可缩放和移动的流程画布；独立识别与摘要分支；直接新建工作流和摄像头组；单次应用当前配置、单帧测试、摄像头组分配和开关；按类型管理列表、删除及恢复 |
| 人员与能力 | 所有摄像头共享的人员库；后端实际支持的检测项目目录及通道配置入口 |
| 事件与回放 | 按通道筛选事件、查看人物与视频证据、加载更早记录 |
| 输出与集成 | 按通道显示实际视频流、JSON、SSE、GVD1、证据、JPEG 和状态接口及复制 |
| 部署与设置 | 分析服务、人物追踪、视频默认值、凭据、启动与测试五组配置；线路测速和浏览器摄像头工具 |

实时工作台每路视频旁直接展示两个独立面板：「全画面描述」只显示 Canvas 定时 Summary 节点返回的全局场景描述，按该节点配置的周期更新。未启用 Summary 时显示未启用状态。每次定时生成同时保留中英文描述，正文跟随页面语言即时切换；没有对应语言版本的旧记录会等待下一次摘要，不回退显示其他语言。
「任务实时判断」按当前选中的事件显示独立卡片，颜色直接来自快速 events 的返回：发现为红色、未发现为绿色、不确定为黄色、尚未返回为灰色；不等待定位、人物关联或连续事件确认。停止或切换任务会清除旧颜色。无需打开页签即可查看这两项内容；
窄屏下按顺序排列。逐帧分析记录保留在「实时结果」页签内，该页签只显示记录。
各路使用明确的功能页签：

| 页签 | 用途 |
| --- | --- |
| 视频接入 | 填写或保存本路视频地址、选择摄像头类型、连接或断开预览 |
| 检测任务 | 选择本路检测项目与敏感度、保存设置或放弃草稿 |
| 实时结果 | 查看本路逐帧分析记录 |
| 播放设置 | 读取和保存本路网络视频缓存时间，允许范围为 0–30 秒 |
| 服务诊断 | 检查本路连接、运行状态和服务数据 |

先在「视频接入」连接视频，再进入该路「检测任务」选择任务与敏感度，最后在工作台顶部统一开始分析。
分析期间的原有设置锁定规则继续生效；停止分析保留视频预览。
切换页签保留本路连接和未保存的检测草稿。每路「事件回放」入口会进入统一的
「事件与回放」页面并自动选中该通道；该页只有一个通道选择器，不再另列主通道记录。
播放缓存直接在「播放设置」中调整，运行中也可保存，重启后保留；调小缓存会跳过旧画面，追上最新结果。
浏览器摄像头工具在「部署与设置」中独立提供，用于本机摄像头预览检查。
也可以在[工作流](workflows.md)中配置并应用到摄像头组；应用与组开关要求受影响摄像头停止分析。
受工作流管理的摄像头从画布读取检测选择，移出组后在下次开始时恢复原有手动设置。

输出页从 `GET /v1/fleet` 的 `cameras[].outputs` 读取地址。通道切换同时更新链接与
复制内容；没有返回的接口不生成猜测地址。播放缓存和服务诊断统一保留在实时工作台
对应通道中，输出页不再重复提供主通道设置或诊断。

能力页和输出页只展示已有功能，不再显示规划中的规则、检测任务、自动动作、
留存策略或业务应用占位。实际 Webhook 交付继续沿用现有服务配置。

部署设置通过页内索引定位五组配置，常用字段直接展开，所有部署字段共用上方固定的
保存和放弃修改操作。线路测速、云 GPU 租用和本机摄像头保留各自具体操作，避免
混入统一的杂项面板。

界面使用能力名称，不显示模型名称。自备服务标识保留原字段及保存协议，以密码输入框
显示；诊断 JSON 只隐藏模型标识，保留延迟、置信度、人物标识等业务数据，原 API 数据不变。

## 动态检测项目

控制台通过 `GET /v1/ui/info` 的 `event_catalog` 读取后端当前支持的事件。
各路「检测任务」从本路 `analysis/settings` 响应读取相同格式的目录，按该路返回值生成
选项；保存仍使用原有的 `features` 和 `event_sensitivities` 字段。
任务概览、检测复选框、敏感度、历史筛选和视频标注共用目录中的名称。
“刷新检测项目”会重新读取主通道目录和已加载通道的设置，有未保存修改的通道保留草稿。
主通道保留仍有效的选择和参数草稿；重新进入逐路「检测任务」时读取该路目录，
有未保存修改时保留草稿，可用“放弃未保存修改”重新读取。
目录不可用或版本不支持时显示错误并禁止提交相应设置，不猜测可用事件。

目录版本为 `1`，`events` 是有序数组，空数组表示没有可用事件。每项包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定的事件 ID，用于请求与结果关联 |
| `labels`、`aliases` | 中英文名称和旧名称别名；未知历史 ID 仍以文本显示 |
| `default_enabled` | 首次加载时是否默认选中 |
| `kind` | `detection` 或 `identity`，区分事件与身份展示 |
| `scope` | `person` 或 `scene`，区分人物与场景事件 |
| `sensitivity`（可选） | 默认值与选项数组；缺失时不生成敏感度控件 |

敏感度选项沿用 `value`、`label`、`description`，也支持 `labels`、`descriptions`
中的 `zh` / `en` 文案。UI 不限定选项值为 standard/high，实际合法值由后端校验。
后端适配器 `event_catalog.py` 从检测器支持列表与敏感度策略生成目录；显示名称、
范围等元数据集中在 `EVENT_PRESENTATION`。新增后端事件会自动出现，没有名称元数据
时先显示 ID。无需在 HTML、逐路控制器和标注代码中再维护事件名单。

目录只是展示契约，不会启用尚未实现的检测器。推理、事件确认、清除、追踪和归档
仍由现有流程负责；更换内部实现时保持这些公开接口的语义即可复用控制台。若新增
全新的参数类型或改变接口语义，需要扩展契约和通用控件，而非为单个事件写页面逻辑。

前端回归覆盖导航后草稿保留、通道输出关联、失联后的链接禁用、复制降级、
各路配置页签、画面旁分析面板、播放缓存设置、集中通道回放、输出接口及显示层保密。
实际推理性能与准确率不属于界面验收。


Canvas 取消选择事件时会同时移除该事件的敏感度设置；重新选择时使用该事件的有效默认值。至少保留一个事件，如需暂停事件分支可关闭模块。Summary 的间隔为 1–3600 秒，指令最多 4000 字符。测试和应用前会检查完整的输入到输出连接；切换工作流、摄像头或修改配置会作废旧测试返回。

Canvas 的「人物追踪」是独立模块：将工作流输入的 `frames` 接入人物追踪，再将 `tracks` 接入输出。每个工作流最多放置一个人物追踪模块，可以在工作流、摄像头组或单路摄像头范围关闭；它不改变快速事件判断与 Summary 的选择。

模块的开关表示工作流配置，旁边单独显示追踪服务是否已配置。尚未配置服务时仍可编排并应用工作流；启用该模块的测试和分析需要先在「部署与设置」完成服务配置。显示「追踪服务已配置」只说明部署配置齐全，开始分析时还会检查服务是否就绪。连续人物描边与人物编号需要实时分析，单帧测试不会证明持续追踪效果；配合人脸识别和带位置的事件检测后，可持续关联人物身份与事件。

Canvas 只有一次「应用」操作：提交当前编辑内容，并同时更新所有已关联的摄像头组，不再先保存再应用。尚未分配组时可只应用工作流配置，或在应用面板选择组；之后可通过「摄像头组分配」加入其他组。任一关联摄像头处于开始、运行、测试、停止、清理或状态不可用时，工作流配置与连线均锁定；未应用更改会保留，停止后可继续编辑和应用。浏览、缩放、平移、切换工作流及创建副本仍可使用。
