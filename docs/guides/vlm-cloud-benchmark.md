# 纯 VLM 十二路：一键云端测试

入口：`tools/vlm_benchmark/run_remote.sh`。从 Mac 运行，它会打包当前代码和视频、
上传到一个实例、安装独立环境、检查真实模型请求、跑分阶段测试，并下载报告。
不用手动上传 SAM 权重、注册 Supervisor 或建立浏览器端口隧道。

## 测试范围与准备

本轮沿用 Harness 的**外部 VLM API**，测试优化后的纯事件分支和共享队列。
租用实例的 CPU 负责送帧、请求和结果处理，**GPU 不承担 VLM 推理，也不是本测试的必需条件**。
本脚本没有在实例上部署 VLM 权重。如果后续要测本地部署模型，需要单独确定模型和推理服务，
不能把这里的结果当作单张 RTX 4090 的模型容量。
云端执行依赖 Linux/POSIX；计划、打包与报告模块可以跨平台导入，Windows CI 仅跳过
POSIX 文件锁及实际云端执行的测试，模型解析和共享调度测试仍执行。

准备：

- 一个 Linux x86_64 实例，Python 3.12（例如已有 Python 3.12 的 CUDA/PyTorch 模板）；
  glibc 至少 2.28，可访问 PyPI 和所选模型 API。预留至少 3 GiB 空间用于安装，另加视频空间。
- SSH 地址、端口，并把本机 `~/.ssh/id_ed25519_vast.pub` 加入实例。
- 对应提供商可用的 API key、模型权限与额度。密钥在本机隐藏输入后通过 SSH 标准输入传递，
  不写入命令参数或本地打包文件；云端临时密钥文件权限 0600，读取后删除。
- 默认视频：`/Users/bihaotian/Downloads/output 3.mp4`。可用 `--video '/其他路径.mp4'` 替换，
  也可重复给出多段视频。

当前默认提供商为 `aiclub`，模型由项目路由解析；若使用 OpenRouter，显式指定
`--provider openrouter`。`--model` 可以固定该提供商支持的模型名称。
同一组比较保持提供商、模型、输入视频和参数相同；报告保存实际解析的模型名。

## 开始测试

在 **Mac 终端**运行，替换 `YOUR_HOST` 和 `YOUR_PORT`：

```bash
cd /Users/bihaotian/.codex/worktrees/locateanything-sam/goodvision-harness-main
bash tools/vlm_benchmark/run_remote.sh \
  --host YOUR_HOST --port YOUR_PORT
```

先按提示输入 SSH 私钥口令（如有），再输入所选提供商的 API key。
脚本也可读取 `INFERENCE_API_KEY` 或对应的 `AICLUB_API_KEY`、`OPENROUTER_API_KEY`、
`DASHSCOPE_API_KEY` 环境变量。无需把密钥发到聊天中。

完整流程：

1. 创建独立的 `/workspace/goodvision-vlm-tests/<run-id>/`，校验上传文件 SHA-256；
   安装独立 `.venv`。不会重启已有 SAM 服务。
2. 用真实视频做一次隔离请求探测（3 秒送帧、0.25 个窗口/秒，共一个请求）。
   只检查接口能否返回完整结果，超过 3 秒的有效回复仍可证明接口可用；
   HTTP 超时仍为原来的 5 秒。无完整结果或输入无效会停止后续测试。
3. 在同一实例、同一配置下测 **1、4、8、12 路，各 30 秒、各重复两次**。
4. 十二路的两轮短测都符合下述工程门槛后，再跑 **十二路 15 分钟**。
   未通过则跳过持续测试，保留逐路失败原因。
5. 自动下载 HTML、JSON、请求记录、进程统计与 CPU/内存遥测。

任一短测轮次收到 HTTP 429 时，脚本会结束当前有界轮次后停止后续轮次和升档，
保留结果并报告失败；不会自动重试或接着运行持续压测。该保护不在首个 429 到达时
立刻终止所有在途请求，因此当前轮次内仍可能出现后续错误。应先查明限制来源再发起新测试。

默认每路每秒 1.25 个观察窗口，每个请求包含同一路最近 2–4 帧；
总并发 16、每路并发 2、请求发起上限 20 次/秒、等待名额上限 1 秒。
每路使用独立生产 VLM 分支进程，输出 fight、smoking、fall、weapon 四项判断。

请求预算是上限估计，不是美元报价：探测 1 次、短测最多约 1,900 次，
条件触发的持续测试最多约 13,500 次，合计 **15,401 次**。跳过持续测试时不发生那部分请求。
费用取决于模型、输入图片与 token 计价；没有自动充值或无限重试。

仅做短测可加 `--soak-seconds 0`，但结果不会被标记为完整十二路持续容量验收。
只诊断单路时使用 `--streams 1 --soak-seconds 0`：仍保留原来的频率、并发、
3 秒目标和两轮 30 秒测量，不降低门槛。预算上限约 77 次请求。
同一实例已经上传过相同视频时可加 `--reuse-video RUN_ID`，仅上传新代码，
在云端复制该旧任务的视频并校验哈希。旧任务目录必须仍存在，新旧结果各自保存。
`--compare` 会在每档交替测试关闭共享限流与开启共享限流的条件（ABBA 顺序），
保持同样的 `events` 提示和输入；短测预算翻倍。该对照只测调度差异，不代表旧版所有功能。
对照测试会使用同一个模型账户，禁止同时从其他终端启动压测。

## JSON 修复后的单路并发 2/4 对照

先验证事件输出格式，再比较每路的在途请求上限，保持单路视频、
1.25 窗口/秒、3 秒目标、5 秒 HTTP 超时和 160 tokens 输出预算不变。
在同一实例上按 **2 → 4 → 4 → 2** 的顺序运行，每轮 30 秒。
这不是两路/四路视频，也不是每次请求装入 2/4 个观察窗口。
本地工作线程均为 4，仅改变共享调度中的每路在途请求上限。

当前实例和已上传的视频可以使用以下 Mac 命令：

```bash
cd /Users/bihaotian/.codex/worktrees/locateanything-sam/goodvision-harness-main
env -u INFERENCE_API_KEY -u OPENROUTER_API_KEY \
  bash tools/vlm_benchmark/run_remote.sh \
  --host 115.75.223.236 --port 46416 \
  --identity ~/.ssh/id_ed25519_vast \
  --provider openrouter \
  --model 'qwen/qwen3.5-35b-a3b:nitro' \
  --video '/Users/bihaotian/Downloads/output 3.mp4' \
  --reuse-video 20261004T143557Z-333bc1c7 \
  --streams 1 --soak-seconds 0 \
  --event-json-mode schema --compare-concurrency
```

密钥仍由用户隐藏输入。只上传新代码，复用同一实例已有的视频并校验哈希。
若旧实例/任务已删除，应去掉 `--reuse-video` 并改成新实例地址。
预算上限为 **153 次模型请求**：一次隔离探测，加四轮各最多 38 次；
不启动十二路或十五分钟持续测试。格式探测失败、401/403 权限错误、
输入时钟/记录/排空异常时停止，保留部分结果，不能将其视作完成对照。
探测通过后，某档没有有效结果仍会继续测另一档；零结果的轮次照常计为失败。

`--event-json-mode schema` 通过 OpenRouter 的
[结构化输出](https://openrouter.ai/docs/guides/features/structured-outputs)
声明四个必需字段及 boolean/null 类型，并使用 `provider.require_parameters=true`
筛选支持相应参数的路由。保留原模型、关闭推理和按吞吐排序等路由设置。
如果没有可用的支持路由或接口拒绝请求，测试失败；不会静默取消约束。

解析器只接受完整 JSON，兼容一个完整外层的 Markdown JSON 代码块；
缺字段、多字段、重复键、错误类型、额外解释、截断或未正常结束的 completion
继续计为失败。不会自动修补 JSON 或把不确定的 null 转成 false。
诊断记录包含错误类别、结束原因、回复长度和外层格式，不保存回复原文或密钥。

报告并列展示两档的完整有效结果、及时结果、校验失败、请求超时和排队丢弃；
逐轮门槛和延迟单独保留。若格式错误下降但及时结果比例仍低，说明还需继续分析时效；
若并发 4 缓解丢弃却增加超时，也不能仅凭完成数选择并发 4。
同一 OpenRouter 模型仍可能被分配到不同上游，ABBA 不能消除所有路由或网络波动。
两组都使用修复后的提示、解析和 schema，因此这是当前并发参数对照，
不是与旧报告之间只改变一个变量的修复效果实验，也不能证明十二路已通过。

## 同步与错峰输入对照

`--streams 8 --global-limit 32 --per-stream-limit 4 --soak-seconds 0
--compare-arrival` 在同一实例上按同步、错峰、错峰、同步的顺序运行四轮，各 30 秒。
包含一次探测的预算上限为 **1,217 次请求**。不能同时与其他对照开关使用。
错峰将各路的源时钟均匀分布在一个观察周期内；当前周期 0.8 秒，八路相隔 0.1 秒。
每路仍发送完整的同一组帧，保持原源时间戳、采样频率、计划窗口分母和 3 秒期限。
最后一路结束较晚，所以总输入区间为 30.7 秒，不是缩短某一路或放慢每路播放。

逐路报告保留请求准备、发送、等待响应首字节、读取回复等分段耗时。
各分段有独立样本数，缺失字段不计为零，失败请求中已完成的阶段也计入统计。
部分阶段相互包含，不能直接相加；上传后等待首字节仍包含网络、上游排队和推理，
不能把它单独当作模型计算时间。记录仅保留数值字段，不记录密钥、回复原文或请求头。
对照先检查同步突发是否影响性能；即使错峰通过，也不代表任意相位的真实摄像头都通过。
正式固定错峰输入的测试可使用 `--arrival-mode staggered`，仍需逐路检查两轮结果。

## 报告如何判定

另有 `--compare-routing` 对照：固定一个路数、同一基础模型，以
`provider.sort=throughput → latency → latency → throughput` 运行四轮。
要求 OpenRouter、基础模型 ID（不能含 `:nitro` 等路由后缀）、重复两次、关闭持续测试，
且不与其他对照同时使用。保持图像、提示、schema、速率与时限不变，
各轮实际参数写入 `summary.json`，八路 30 秒对照的请求上限同样为 1,217 次。
正式固定一种路由可使用 `--provider-sort latency`，但提供商选择仍由路由服务决定。
OpenRouter 的 [Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)
区分生成吞吐与响应延迟；Nitro 是吞吐优先的路由变体，不能等同于最低响应延迟。
切换路由不保证性能或识别质量改善，需检查同轮对照及后续重复测试。
专用测试配置显式固定 OpenRouter 的 `reasoning.enabled=false`、回退开关和排除名单，
因此从 Nitro 名称切换到基础模型名时不会遗漏原来仅对默认模型生效的配置。
报告必须核对 `effective_request_parameters`，不能只看模型名称相近就假定其余参数相同。
已知公开上游名称以有限枚举记录在回复结构诊断中，其它名称归为 `other`；不保存回复原文。
既有公开记录隐私过滤器可能将部分上游标签替换成通用名称，不应反推这些记录的具体上游。
`--provider-only deepinfra`（另支持 `parasail`、`venice`）可限定一个上游并关闭回退，
保持其它推理参数不变；不支持相应参数或不可用时会失败，不会偷偷改用其它上游。
先配合 `--streams 1 --soak-seconds 0 --per-stream-limit 4` 小规模筛查，
上限 77 次请求；不与 `--compare-routing` 同用，以免两种排序实际限定在同一个上游。

预先固定的**建议工程门槛**：每一路至少 95% 的计划观察窗口在 3 秒内产生完整结果，
请求错误不超过计划观察数的 1%，完整结果中的不确定判断不超过 10%。
这些是本次脚本采用的筛选条件，**不是会议已经确认的标准**。

分母包含计划但被跳过、缺失或超时的观察窗口。输入送帧迟到、记录缺失、队列未排空、
进程退出及未完成阶段都不能计为通过。每路单独判断，不能用十二路平均值掩盖某一路饥饿。
报告也给出逐路延迟 P95、错误码、HTTP 状态与原始记录。
返回校验错误会单独计数；回复结束原因、内容类型和字符数也会保留为安全诊断，
不保存原始回复正文或密钥。历史记录没有这些新字段时，不能追溯猜测根因。

延迟从“窗口的最新证据进入 VLM 分支”算到结果发布，
不包括摄像头网络、预解码、浏览器显示，也不等于事件开始到第一次正确识别的时间。
视频预解码后按实际时间送帧；长测试循环素材，不通过放慢播放来提高指标。
同一视频复制成十二路只能检验负载，不能证明十二种场景都识别正确。

即使容量通过，也不能宣称事件准确率通过。事件 Precision/Recall/F1、误报、漏报和
首次正确识别时间仍需另用定义一致的行为标注评估；Astra 自动标注需保留不确定性。

## 断线恢复与停止

日志会打印 `Run ID`。SSH 断线后云端任务仍按固定计划运行；恢复监看和下载时用同一实例：

```bash
bash tools/vlm_benchmark/run_remote.sh \
  --host YOUR_HOST --port YOUR_PORT --resume RUN_ID
```

停止本脚本启动的任务并取回已有结果：

```bash
bash tools/vlm_benchmark/run_remote.sh \
  --host YOUR_HOST --port YOUR_PORT --stop RUN_ID
```

本机 `Ctrl+C` 会尝试停止对应云端任务；如网络已经断开，请重连后使用 `--stop` 确认。
同一实例只允许本脚本的一个测试套件运行；锁不会管理手工启动或其他项目的负载，
因此测试期间也应停止这些额外负载。不要用新命令重复发起任务来代替 `--resume`。

结果下载到 `outputs/vlm-cloud/<run-id>/results/report.html`。
`manifest.json` 保存输入与代码哈希、软件版本和实例信息，`summary.json` 保存固定计划及判断。
失败阶段留下的原始记录可以诊断，但不作为完成的测量。
下载成功后可以自行关闭租用实例；**脚本不会自动停止或销毁实例，租用计费不会因此自动结束**。
