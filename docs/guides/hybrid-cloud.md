# 本地显示与云端分析协作部署

浏览器在本地读取摄像头、解码和显示原始画面，保留播放缓冲、低分辨率运动估计、轮廓传播和最终绘制。
Harness 的分析调度、事件请求、事件确认与融合运行在租用服务器的 CPU 上；SAM 保留在同机 GPU。
每路浏览器上传一次分析 JPEG，云端 Harness 在原有采样率下分流给事件服务和 SAM。
SAM 使用云端 loopback JPEG 传输，避免本地 JPEG 解码再转 H.264 的环节。模型输入缩放和 SAM 进程中的 JPEG 解码仍存在；这不是零拷贝或“全链路只解码一次”的实现。

## 启动

控制机安装 `python-dotenv`、`vastai` 并提供 OpenSSH。沿用 `.env` 的 `VAST_API_KEY`、`HF_TOKEN`、`SAM_SSH_KEY` 和现有事件服务配置。
下面命令会实际租用并开始计费：

```powershell
python tools/start_sam.py --hybrid-analysis --gpu-name RTX_3060_Ti --streams 2 --disk-gb 50 --analysis-port 8280
```

就绪后打开 `http://127.0.0.1:8280` 和 `http://127.0.0.1:8281`，分别使用两路独立控制台。
本入口不合并成舰队控制台。可以改用 `--gpu-name RTX_4090`，每个 GPU 型号的实际性能仍需实测。
视频文件路径若交给服务器读取，指云端文件系统；本地视频回放测试应在浏览器读取本地文件，不能把本地路径误作云端路径。

CPU 应用使用独立 Python 环境，不改变 SAM 固定的依赖。CPU 应用禁用 CUDA，可用的 GPU 资源留给 SAM。
浏览器分析采样率与跟踪采样率保持独立，不降低事件采样率来适配 SAM。

所有控制台在远端与本地均仅监听 loopback，通过 SSH 访问。只传输明确允许的事件服务配置；不向 CPU 应用上传云平台密钥、SSH 私钥或 HF token。
事件服务配置经 SSH 标准输入写入权限为 0600 的临时运行配置，进程启动读取后删除，凭据不出现在命令行。
云端的分析日志和事件证据在 `/workspace/goodvision-sam/analysis/data/camera-NN/`；释放租用前下载需要保留的证据。

保持启动器运行。Ctrl+C、SSH 退出或任意云端子进程退出都会进入停止与实例释放流程；关闭浏览器不释放实例。
复用既有的未确认清理保护，若平台不能确认释放，核对对应实例后才能继续租用。

## 验证

双路使用相同原始样本，分别设置播放缓冲 2/3/4 秒；同时采集本地 CPU、云端 CPU、GPU 显存、播放速度、呈现帧率、描边覆盖率及事件成功/失败。
保留事件服务模型、敏感度、输入分辨率与采样率，对比已记录的 main 基线；录屏本身作为额外负载，另做无录屏播放对照。
新配置的显存、云端 CPU 与内存需求不能直接沿用 SAM-only 部署的结论。
