## 1. 目标定义（标注和问法共用这一份）

**算"有可辨认的刀"：** 画面中至少有一帧，刀刃足以认出是刀。刀柄、刀枕看不见也算。刀在包里、正被拿出来，或者拿在手上，都算。

**不算：**
- 只有金属直边、反光，或者认不出是刀的条状物；
- 尺子、笔、平板边框、餐具或刀的图片、印刷品；
- 刀完全被遮住、画面上看不见：这是按画面看不见来标，不代表包里没有刀。

**标注粒度：** 以片段为单位，只判断这一段里有没有可辨认的刀，不标时间区间（第 7 版）。

## 5. 计分规则（D、V、T 同一口径）

- **逐片重置：** 每段视频从一个新的节点实例和新的 session 开始，状态不跨片段。
- **新检出：** 保持状态从「不在」变为「在」的那一次判断（`changed = true` 且 `present = true`），时间以该次判断的源帧时间 `timestamp_seconds` 为准。
- **正样本：** 片段内出现任何一次新检出，就算召回（片段级，第 7 版）。另外报告最早一次新检出的源帧时间，供人工抽查是否早于刀出现。
- **负样本：** 任何一次新检出都算误检。
- **片段得分（用于选型）：** 全片所有有效判断中，「在」为最高概率选项时的最大概率；没有则记为 0。

## 6. 选择规则（在 F1 写死，只用 D 和 V）

- **第 1 步，在 D 上选方案：** 比较 4 个候选的分离度，即"正样本的最低分减去负样本的最高分"。依次比较以下四项，前一项相同才看下一项，不做临场判断：
  1. 分离度大的胜出；
  2. AUC 大的胜出；
  3. 帧数少的胜出（2 帧优先于 4 帧）；
  4. 问法 1（当前预设）优先于问法 2。

  X 只报告，不影响选择。
- **第 2 步，在 V 上定门限：** 只用选出的方案，按复核后的标签，排除争议样本。
  - 正负完全分开时，门限取两者中点；
  - 分不开时，在 0.50–0.99（步长 0.01）中选让 TP − FP 最大的门限，相同时取更高的门限；
  - 门限下限是 0.50。
- **第二次冻结（F2）：** 写入方案、门限、精确的代码提交号、模型版本和服务参数，然后才能下载并运行 T。

## 7. 试点识别目标（排除争议片后计算）

路线一用 T；路线二用 T′，结果一律标为「有先验暴露的试点」。

设 P、N 为排除争议片后的正、负样本数。保管人在 F1 时只公布 P、N 两个数（不对应具体是哪几段）。通过线在**看任何分数之前**，按下面的公式算成整数，写进 F1 冻结凭证；之后不再调整。

| 条件 | 规则 |
|---|---|
| 最少样本数 | P ≥ 3 且 N ≥ 6。不满足时，结果记为「样本不足，无结论」，不算达标 |
| 允许漏检 | floor(P / 5) 段：P = 3–4 时为 0；P = 5–9 时为 1；P = 10–14 时为 2 |
| 允许误检 | max(1, floor(N / 10)) 段：N = 6–19 时为 1；N = 20–29 时为 2 |
| 两种运行配置 | 「只开物体节点」和「事件 + 物体并行」**各自**都要达到以上目标 |

- 不达标：预设继续标为不可用，结果照实报告，不能据此回头修改方案、门限或标签。
- 达标：只能说"刀具，在这批翻包试点素材上达标"，并附上 F1 记录的素材限制，**不能证明可以推广**。

## 8. 运行验收

- **调通路径：** 只用 V 和 D，不用 T。
- **测试路径：** 在 GPU 机上运行真实的 `HarnessRuntime`、生产版 `videojev_service` 和本地 RTSP 源，按实时速度推流。服务参数用生产默认值。
- **三组配置：**
  1. 只开 System 1 事件节点（作为基线）；
  2. 只开物体节点；
  3. 事件节点 + 物体节点并行。
- **预热：** 服务启动后，先用一段不属于 V、T 的画面推流 60 s，这段不计入结果。
- **时长：** 调通运行时，每组把 V 的各段按实时速度依次播放，循环到 300 s 为止；T（或 T′）运行时，每段完整播放一次。
- **逐片边界（按节点分别定义，时间以该片源视频时间计，0 = 第一帧）：**
  - **开始有足够帧的时点 t0：**
    - 物体节点 · 采样 A：第一帧之后的第一个判断时点，即 1 / sample_fps，这时有了"上一次判断的帧"；
    - 物体节点 · 采样 B：凑够 4 帧、间隔 0.4 s 的最早时点，即 1.2 s 之后的第一个判断时点；
    - 事件节点：凑够两帧、间隔 0.5 s 的最早时点，即 0.5 s 之后的第一个判断时点。
  - **应发请求的时点：** 从 t0 开始，按节点频率排出的、源视频时间不晚于最后一帧的所有判断时点。物体节点每 1 s 一次，事件节点每 0.8 s 一次（1.25 次/秒）。
  - **截止时间：** 每个应发时点的请求，只有在发出后 20 s 内（服务的请求时限），并且不晚于"最后一帧 + 20 s"拿到有效结果，才算有效。到这个时间，该片的节点实例停止并重置。
- **有效判断覆盖率（按节点分别计算）：** 有效结果数 ÷ 应发请求的时点数。
  - t0 之前的时点属于"等待首批帧"，不进分母，单独报告次数；
  - t0 之后应发请求的时点，只要没有在截止前拿到有效结果，都留在分母里，并按原因分别计数：无帧（`no_frame`）、无新帧（`no_new_frame`）、因上一个请求未完成而错过（`missed_busy`）、`queue_full`、`superseded`、超时、无效响应、截止后才返回；
  - 节点按固定网格 start + k × 间隔排时点，慢请求之后不补发、不堆积，被错过的时点以 `missed_busy` 记录；每条记录带 `planned_index`，能唯一对应到原计划时点。`eligible = false` 只表示没发请求，不表示可以从分母扣掉；
  - **唤醒迟到容差：** 每个计划时点发出前都重新读一次实际时钟。只要不晚于计划时间 + min(0.25 s, 间隔 / 4)，就照常发出（1 fps 时为 0.25 s）；超过就不发，也不补发，按原因记账并留在分母里：计划时点落在上一个请求执行期间的，记 `missed_busy`；其他情况（线程醒得晚、日志回调慢等）记 `late_wakeup`；
  - **时钟对齐：** 节点按自己的单调时钟排时点，零点不一定等于源视频的 0 s。正式计分前，每片都要记录节点时钟起点，以及每一帧到达时的节点时钟和对应的源视频时间，用实测偏移把每个计划时点换算成源视频时间，再套用 t0 和截止规则。偏移值和换算方法写进证据记录。
  - 这样"等待首批帧"和"服务漏处理"不会混在一起。
- **前置改动（不用 GPU）：** 节点要先能逐时点记录：计划时点、是否应发、实际发出时间、结果或原因。这部分和采样 B 一起在 F1 之前合进 PR，附上测试。
- **每组记录：**
  - 源帧间隔和完成间隔，分开报告；
  - 请求耗时 P50 / P95（nearest-rank）；
  - 各类错误计数；
  - 覆盖率；
  - 并行时事件相对基线的 P95 耗时变化和错误率变化。
- **通过标准（试点）：**
  - 每组、每个节点都没有超时；
  - 每个节点的覆盖率都 ≥ 99%；
  - 第 3 组里，物体请求耗时的 P95 ≤ 1.0 s；
  - 第 3 组相对第 1 组，事件请求耗时的 P95 增幅 ≤ 50%，事件错误率增幅 ≤ 1 个百分点；
  - 源帧间隔的 P95 ≤ 1.5 × 配置间隔。
- **范围：** 只测单路视频，多路吞吐不在本轮。
