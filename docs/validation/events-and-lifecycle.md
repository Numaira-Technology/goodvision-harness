## 独立发布与事件定位

当前默认 `SCENE_INDEPENDENT_VLM=true`。VLM 独立采样原图、执行时序请求并按源顺序发布，后续 SAM 人物关联和归档不应阻塞原始事件报告。每轮进程绑定 source/session/generation，旧轮结果不能覆盖新轮状态。轻量状态接口避免等待归档和追踪锁；传输就绪不代表标签完整或识别正确。

事件有效性与人物定位分开：可靠的事件布尔值和置信度可以保留，即使框缺失或无效；无定位的判断不能为具体人物确认、解除事件或关联身份。缺失标签、空回复和失败属于未知，不能当作阴性。`observed_detected` 是本次模型观察，`detected` 是确认语义，`analysis_complete` 与 `localization_complete` 分别记录标签和定位完整性。真实模型验证见[识别质量](recognition-quality.md)。

这取代了早期“任一框无效就拒绝整份报告”的处理方式。无效 JSON、不可靠事件字段仍明确失败，不猜测坐标系、不制造人物框。

## 归档延迟

历史现场记录确认：同一事件已持久入队后约 **79.645 秒**才创建归档。该结论适用于 `/v1/events` 链路，不应外推为所有 `/v1/results` 输出都等停止后才发布。

当前归档将录像写盘和编码交给证据工作线程，先持久保存任务描述；JSON/SSE 读取已发布快照，不等待写入锁；持久化仅序列化发生变化的记录。事件元数据可先到达，录像通过 `evidence.status` 和后续更新报告就绪情况。任务重启恢复与提交失败重试均有回归覆盖。

后续提交审阅补齐了“事件已修订、旧录像尚未写盘就重启”的边界：旧版本已接纳任务继续完成并保留不可变录像，但不会重新挂回当前已撤回或过期的证据指针。该场景在修复前复现失败，修复后与已写盘任务一并回归。

2026-09-21 的隔离 HTTP 探测用历史数据库副本和替代编码器，以每秒 5 次更新发送 40 次事件，写盘人为阻塞 5 秒：40/40 更新收到，其中 25 次在阻塞期间到达；提交到 SSE 的中位数/P95/最大值为 **162/285/317 ms**，最终队列归零，无丢弃和存储/编码失败。该数据不是线上延迟承诺。

修复曾随 `20260921-receive-fix1` 于 2026-09-21 13:08:46 北京时间部署到 8080；健康检查通过时分析保持停止。**部署后的真实识别、录像写盘与接收方持续消费联测仍缺少验收结论。** 运行时可用 `event_archive_timing` 区分入队等待与处理耗时。

## 身份纠正和停止流程

| 问题 | 保留的修复约束 | 回归入口 |
| --- | --- | --- |
| 已登记人物重新匹配后仍保留陌生人误报 | 仅消费真实 `face_match` 确认；按 run、主体和源时间撤回已证明属于同一人的历史误报。保留事件 ID 和历史版本，不能凭历史姓名免除未来检测 | [身份纠正](../../tests/test_stranger_identity_correction.py) |
| 源时间异常前跳使有效证据被判过期 | 对异常 PTS 重建时间基准；正常抖动、真实断流间隔和单调性继续保留 | [源时钟](../../tests/test_stream_timing.py) |
| 跟踪失败导致 VLM 在途结果丢失 | 停止后先发布已接纳 VLM 请求的结果，再结束进程；跟踪真实错误仍可见 | [独立 VLM 服务](../../tests/test_vlm_independent_service.py) |
| 复用线程的空跟踪会话无限收尾 | 两种队列策略都处理无帧结束；不伪造远端会话或推理结果，下一轮仍可正常运行 | [跟踪流水线](../../tests/test_sam_tracking_pipeline.py) |
| 归档写盘阻塞实时元数据 | 写盘/编码与事件发布分开，读取不等写锁；恢复超过队列容量的任务也必须完成 | [归档延迟](../../tests/test_archive_stream_latency.py) |

身份修复曾以同一批 137 条真实已保存输出分别回放旧版和修复版：旧版保留 unknown，修复版撤回误报；这不是新的摄像头或人脸模型精度测试。私有证据位于 `.goodvision/diagnostics/frank-stranger-20260918/`。

## 未关闭的边界

后续身份关联可因 SAM 长期落后而过期；VLM 临时原图缓存不等于每帧永久留档。私有人脸/追踪事实可用于恢复，不能据此声称全部后台人物整理已支持进程重启后自动续跑。状态锁隔离修复也不代表所有共享锁耗时已被消除。

下一轮需在完整多路分析中验证停止、重启、故障恢复和 JSON/SSE 持续输出。归档隔离探测原始结果在 `.goodvision/diagnostics/archive-stream-fix-20260921/stream-probe.json`；独立 VLM 历史回放资料在 `.goodvision/diagnostics/vlm-independent-20260921/`。
