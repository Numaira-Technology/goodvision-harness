# 极低分辨率专项测试与修复记录

日期：2026-09-10；分支：`codex/person-event-evidence`；本轮实现基线：`057c1ae`。

**流程验证达到预期，极低分辨率识别准确性不能判定通过。** 真实模型在低清素材中
存在明显漏检，人物框也不足以支撑可靠的跨帧关联。本轮修复了五类可复现问题，
保留原始失败记录，分别报告真实模型结果、理想人物框对照和合成流程测试。
没有更改线上配置、采样频率、并发、最新结果优先规则或当前阴性的即时输出语义。

后续对 8081 的陌生人/吸烟配合问题另做了诊断与修复，见
[联合验证记录](stranger-llm-interop-20260910.md)。后续版本将本地人脸与远程事件
独立调度、独立发布，保持各分支最新结果优先；下文原始模型数据不因该修复而重写。

冒充摄像头录像。使用本地已有的公共视频缓存，并补充下载公开图片和人脸测试视频。

[来源清单](low-resolution-sources.json)。

事件模型主实验为 **37 个源帧 × 6 档 = 222 次真实请求**；另有 12 次公共图片请求、
24 次人物辅助输出成本对照、32 次格式诊断/失败样本重测及 4 次前置探测。
源画面按原比例降采样至长边 320、160、96、64、32，另保留原尺寸，JPEG 质量 75。
未裁剪或先放大后冒充高清。记录实际解码帧号、源 PTS、输入尺寸和 JPEG SHA-256；
不能把要求的 seek 时间直接当成实际帧时间。

事件真值由本次评估代理对原画面逐帧目视检查，**不是独立人工标注的权威测试集**。
跌倒准备阶段、难判边界及倒地后的静止状态不计分，未把静止躺地强行标为正常。
失败响应计为缺失，不算阴性或正确拒报。不同人脸身份只以临时编号表示。

主实验显式使用已有 OpenRouter 路由的 `qwen/qwen3.5-35b-a3b`，temperature 0、

本轮没有为测试更改保存的 `.env` 或配置文件。

## 人物框与身份连续性

将上述真实模型保存的 actors 送入实际 `PersonRegistry`，并与 CAVIAR 官方人物框
做一对一匹配。采用 IoU≥0.3 的宽松门槛，6 帧共有 18 个标注人物观测：

| 输入长边 | 匹配到官方人物框 / 18 | 获得 subject_id 的匹配观测 |
| --- | ---: | ---: |
| 原始尺寸 | 5 | 5 |
| 320 | 4 | 4 |
| 160 | 0 | 0 |
| 96 | 4 | 0 |
| 64 | 0 | 0 |
| 32 | 0 | 0 |

96 档匹配框的置信度不足，因此没有绑定人物。IoU≥0.5 的更严格统计也保存在结果中。
整体只有原尺寸的一对相邻有效关联可评估连续性；其余大量观测缺失或定位不足。
不能把“零身份切换”解读为模型追踪成功，也不能用未标注片段的同 ID 数量充当正确率。

为独立定位本地关联问题，另外直接输入**官方理想人物框**，跳过模型检测，比较修复
前后。时间间隔均不超过 3 秒失检容忍值；这不是 GPU 检测器准确率测试。

| 源时间间隔 | 错误继承：前→后 | 正确连续关联：前→后 |
| --- | --- | --- |
| 0.2 秒（5 FPS） | 0→0 | 113→101 / 120 |
| 0.4 秒（2.5 FPS） | 2→0 | 55→49 / 60 |
| 0.8 秒 | 0→0 | 23→19 / 30 |
| 1.6 秒 | 2→0 | 3→1 / 15 |

交叉区间原先重建的轨迹会丢掉上一帧歧义，再按重叠率错误继承对方。修复后延续歧义
状态，重新建立可靠关联；本对照串人 4→0，但轨迹切换总数 31→55。多人的普通同向
移动对照保持连续；预测框不刷新真实观测时间。更保守的重建可能把历史事件拆得更多，
因此这项修复消除的是已复现的错误继承，不代表连续率全面提升。

真实人脸路径使用已有 InsightFace 1.0.1、ONNX Runtime 1.29.0、`buffalo_l`，在 CPU
运行。图库只在临时目录中创建并清理；另外验证了只读复制原图库，不改写原图库。
David 主实验以 **0.5 FPS** 从 5 到 29 秒取 13 帧，涵盖角度、光照和运动；每档复用相同真实模型
观测，分别测原始匹配、冷启动追踪、先有清晰身份再退化。

| 输入长边 | 检出人脸 / 13 | 原始输入中的脸宽 | 原始匹配已知 / 冷启动已知 | 清晰身份起步后已知 / 13 |
| --- | ---: | --- | --- | ---: |
| 原始 320 | 13 | 33–63 px | 12 / 12 | 12 |
| 320 | 13 | 33–63 px | 12 / 12 | 12 |
| 160 | 13 | 17–32 px | 12 / 12 | 12 |
| 96 | 13 | 10–19 px | 0 / 0 | 4 |
| 64 | 13 | 7–12 px | 0 / 0 | 4 |
| 32 | 8 | 3–6 px | 0 / 0 | 0 |

96/64 档短暂保持身份，随后几何连续性不足而变为不可用；这不是把人改判陌生人。
32 档有 5 帧根本没有检出脸。各档恢复原始画面后均恢复已知匹配。
David 独立录入照的脸约 68×98 px，不满足生产 80 px 的录入下限：**仅此临时评估**
将录入下限设为 60，匹配阈值、识别质量规则及线上录入下限不变。

另按当前默认 **2.5 FPS** 补跑 5.0–9.8 秒的 13 个连续帧：原始/320/160 档全部
13 帧匹配已知；96/64 档仍无法直接确认身份，先有清晰身份时保持 8 帧，另外 5 帧
不可用；32 档只检出 4 帧人脸，全部不能确认身份。六档不同人物对照均未继承错误身份。
该次 CPU 推理中位约 234–500 毫秒，两次本地注册表调用合计中位约 0.19–0.52 毫秒；
这些单机观测不能作为生产吞吐保证。

另用 [OpenCV 高清人脸图片](https://github.com/opencv/opencv_extra/tree/4.x/testdata/cv/face)
`100032540_1.jpg` 按正常 80 px 下限录入。原生脸约 504×738 px；整图缩到 64 长边
时脸仍约 20×28 px，可匹配已知，32 档约 10×14 px 时不可用。这是单图退化对照，
不能证明角度变化或长期追踪表现。固定 640 的检测器输入只会重采样，不会增加源细节。

两个人互为非本人对照。修复前，硬切到另一个人时，只要人脸框重叠就可能继承旧身份；
修复增加脸框面积、形状突变检查，可靠身体轨迹仍使用独立规则。最终双向六档对照
未观察到错误继承，同时保留正常逐步接近、短遮挡和身体连续的回归。只有位置和大小
完全相同的两个不可用人脸时，纯几何信息仍不能保证区分，不能宣称所有换人场景已解决。

## 即时性与人物辅助输出成本

新增处理保持本地、限量、无等待；全量回归继续覆盖阻塞 GPU、录像队列满、编码失败、
归档 I/O 阻塞、乱序结果和当前阳性→阴性。归档事件暂时保持同号，不会让实时阴性变阳性。
本轮没有使用前后多帧投票延迟识别。

真实模型成本对照取 6 个相同源画面，每个重复两次，320 长边、并发 6、同一预算，
将开关两种请求随机穿插。关闭组只从请求中删除精确的可选 actors 说明，其他判断规则、
图片和预算不变；这一开关仅在评估工具内，不改变产品行为。

| actors 辅助输出 | 请求数 | 有效响应 | 平均输出 token | P50 请求秒数 | P95 请求秒数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关闭 | 12 | 12 | 314.83 | 6.05 | 8.57 |
| 开启 | 12 | 12 | 493.25 | 7.03 | 14.52 |

两组事件判断在这些对应样本上相同。开启组平均多 178.42 个输出 token（约 56.7%）。
这是小样本的实际网络请求观测，不是统计显著的性能结论；但**辅助输出没有零成本保证**。
请求耗时包含模型和网络，不含完整直播采样/排队；主表 P50/P95 也包含失败请求。
工具中的 first_completed_latency_seconds 是最早完成记录的单请求耗时，不是完整
`StreamingSession` 首结果时延。前次本地回调隔离测量见
[首次验收记录](event-validation.md#event-evidence)，不能用亚毫秒本地耗时替代真实模型时延。

## 证据视频、故障与修复

**45/45 组合达到预期**：真实 `StreamingSession` → `EventArchive` → FFmpeg →
逐帧解码，产生 55 个事件、53 段可播放 H.264 视频；两个 8 KiB 缓存压力场景按预期
明确证据失败，没有伪造成功视频。这部分输入的是确定性合成判断，仅验证流程。

覆盖 64×36、96×54、160×90、320×180、161×91，源帧率 1/5 FPS，暂停 1 秒归并、
明确停止后再触发拆分、短源、断流、极小缓存；另覆盖同一归档器跨会话的 1920×1080
和 17×9 源。正常视频实际 3.0 秒、15 帧、5 FPS；1920×1080 输出 720×404，17×9
输出 16×8，低清源没有被伪装成高清。每段检查解码帧数、尺寸、像素内容、可 seek 和
元数据；短源与断流保留实际覆盖和原因。

| 问题 | 已实施修复 | 验证 |
| --- | --- | --- |
| 1 FPS 正常源被错误缩成 2.2 秒 | 缓存/预留保留真实后继边界帧；只用它证明覆盖，不作为区间内新观测 | 正常 1/5 FPS 均 3 秒；末尾缺帧仍短，断流不桥接 |
| Windows 临时文件名把有效目标路径撑到 260 字符 | 同目录短临时文件名，保留排他创建、同步和原子替换 | 原失败的 3 个长路径组合全部通过 |
| 人脸框重叠但换人时继承旧身份 | 脸框大小/形状突变检查，身体连续路径独立 | 真 CPU 模型双向不同人物对照与正常运动回归 |
| 双人交叉后互换人物编号 | 将歧义延续到下一次关联，保守重新建轨 | 官方理想框四档独立重播，串人 4→0，断轨增加 |
| 英文 / 中文次序颠倒丢掉完整判断 | 仅在唯一分隔符、明确双语反序时本地交换描述 | 两条保存的真实失败文本 2/2 恢复，不改判断、框或置信度 |

描述格式诊断共 6 次请求，发现两条有效判断仅因语言次序失败。原始主实验的 26 个
失败样本在修复后独立重测，25 次有效，1 次仍是非法 JSON；非法 JSON 继续计缺失，
不猜测补齐判断。重新请求存在随机性，不能把 25/26 宣称为严格配对的修复收益；只有
两条保存文本的离线重解析能隔离证明格式修复。旧 222 次结果完整保留。

## 回归、复现与边界

本轮最终全量回归 **1075 项通过、4 项环境跳过**，耗时 88.61 秒；修改的 Python
文件通过 Ruff。跳过项为 Windows 无符号链接权限的三项打包用例，以及一项 Linux
进程组用例。初次运行有两个测试读取本机已选择的 OpenRouter
路由，却断言配置文件的 AIClub 默认值；用仅限测试进程的 `INFERENCE_PROVIDER=aiclub`
重跑，不修改 `.env` 或把默认值断言改成别的模型。

新增四个可重复使用的评估工具：

来源清单用于审计，并非模型工具可直接运行的 manifest。转换时将每个 clip 的
`clip_id` 映射为 `id`、`source_url` 映射为 `public_source_url`，补充本机 `path`；
将 samples 中 `requested_timestamp_seconds` 映射为 `timestamp`、
`expected_visible_judgments` 映射为 `expected`，保留 null。根节点仍为 `clips` 数组。
公共缓存中的部分视频经过转码；若改用原始数据集文件，应重新检查解码 PTS 和画面，
不能把转码版本的精确帧号不加核对地套用到原文件。

```powershell
# 在此 worktree、已安装项目依赖的 Python 环境运行。
# manifest 的 clips 需要本机 path、public_source_url 和 samples；源清单提供时间及真值。
$env:INFERENCE_PROVIDER='openrouter'
python tools/low_resolution_model_eval.py --manifest samples.json --output tmp/model.json --sizes 0,320,160,96,64,32 --workers 6 --max-requests 222 --timeout 40
# 6 张图 × 两次重复 × 两种 actors 模式，单独测请求成本。
python tools/low_resolution_model_eval.py --manifest cost-samples.json --output tmp/cost.json --sizes 320 --actor-mode both --workers 6 --max-requests 24 --timeout 40
# 使用保存的真实模型结果；不会再调用模型。
python tools/low_resolution_tracking_eval.py --journal tmp/model.jsonl --expected-records 222 --caviar-xml feecp2gt.xml --gt-control --output tmp/tracking.json
python tools/low_resolution_evidence_eval.py --output tmp/evidence-replay
# 人脸工具需要另有 InsightFace + ONNX Runtime 的环境，全部在本地运行。
python tools/low_resolution_face_eval.py --input david.webm --enroll-image david2.jpg --control-input control.jpg --model-root MODEL_ROOT --output tmp/face.json --start-seconds 5 --max-frames 13 --sample-fps 2.5 --enrollment-min-face-size 60
# 主表使用同一命令，把 --sample-fps 改为 0.5，--output 改为 tmp/face-sparse.json。
```

模型工具明确限制请求数；只处理 manifest 指定素材，不连接摄像头、不调用 Webhook、
不读取人脸库。`--resume` 校验配置、路由、评估/解析代码、素材内容和采样清单指纹；
