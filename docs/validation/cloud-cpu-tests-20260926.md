# SAM 3.1 云端 CPU 与双路测试（2026-09-26）

同一段约 55.8 秒的视频、同一台 RTX 4090、同一套云端 SAM 与 CPU Harness 服务，分别测试 0.5、1、1.5、2 秒显示缓冲。每个条件运行两轮。浏览器解码、视频上传、轮廓显示和系统录屏在 Mac 上执行；服务端处理在云端 Linux 实例执行。

| 测试 | 缓冲 | 重复判定 | 关键观察 |
| --- | ---: | --- | --- |
| 单路录屏对照 | 0.5 秒 | 未通过 | 一轮录屏描边率较不录屏下降 4.1 个百分点，超过预设的 3 点容差；描边率低于 70%。 |
| 单路录屏对照 | 1.0 秒 | 证据不足 | 一组对照通过；另一轮录屏只有约 20.8 秒，短于原片，不能用于完整视频比较。 |
| 单路录屏对照 | 1.5 秒 | 重复通过 | 两轮录屏与不录屏的描边率均约 94.5%–94.7%；呈现约 15 FPS，云端 SAM append P95 未明显增加。 |
| 单路录屏对照 | 2.0 秒 | 重复通过 | 两轮描边率约 95%，呈现约 15 FPS，录屏无明显退化。 |
| 单路／双路对照 | 0.5 秒 | 未达标 | 双路各自描边率为 63.9%–69.5%，未达到每路 70%。 |
| 单路／双路对照 | 1.0 秒 | 重复通过 | 两轮的两路描边率为 86.0%–90.8%，各路约 15 FPS。 |
| 单路／双路对照 | 1.5 秒 | 未达标 | 双路描边率为 14.5%–64.9%，出现上传积压，部分新分析采样暂停；第二轮单路对照也降到 0%，说明该档整个系统出现波动，不能归因于双路独有瓶颈。 |
| 单路／双路对照 | 2.0 秒 | 重复通过 | 两轮的两路描边率为 94.6%–95.1%，各路约 15 FPS。 |

原报告曾把 1.5 秒档的“上传积压”警告误当成浏览器未完成；复核逐帧日志确认视频播放和会话排空均已完成。现在将这些警告作为性能现象计入结果，原报告保留在本地 `report-before-review.html` 和 `summary-before-review.json`。修订没有重新运行 GPU 或改变原始日志。

本次测试支持云端服务端处理确实在 Linux 实例运行，并显示 1.5 秒及 2.0 秒下本机录屏不造成明显退化。双路在所测档位中最短重复达标缓冲是 1.0 秒；1.5 秒的非单调失稳意味着还不能宣称双路在所有较长缓冲下都稳定。报告的“描边率”是模型已知人物的显示覆盖率，不是人物检出准确率或轮廓 IoU。两轮、一段视频不足以证明长期稳定，也不能仅凭录屏对照证明全部 CPU 工作已经迁移。
