# 单选抽烟阳性解析失败修复（2026-09-10）

## 根因与现场证据

18:39:41–18:39:55（香港时间）的 smoking-only 会话共 38 次请求，
33 次 `invalid_response`、5 次有效阴性。应用未保存当时失败的供应商原文，
但保存了最新 320×240 源图（frame 225，14.929 秒），可清楚看到嘴边烟具。

经此前用户明确授权，同图、同线路进行了两次近似重放。两次模型均返回
`detected:true`、confidence 0.95、合法双语描述和 cigarette 框，且
`finish_reason:stop`。两次解析异常完全一致：`events must be an array`。

旧配置的通用提示要求顶层 `{detected,confidence,description,objects}`。
单选 smoking 实际走多事件客户端，后者又追加 `events` 数组要求。
模型遵从了旧单事件结构，后端因此拒绝了已识别的抽烟阳性。

## 修复

- 构建多事件请求时保留通用提示中的检测规则，移除其旧单事件输出合同；
  system 明确要求即使只选一项，阳性也必须放在 `events` 数组中。
- 恰好请求一个事件时，兼容旧顶层结构，仅补明确的事件标签和数组包装。
  不改变模型的判断、置信度、描述、烟具坐标或 actor 关联。
- 多选时仍拒绝缺失事件；错误标签、混用 compact/完整结构、无效判断值、
  无效坐标、阳性无框、阴性有框等仍会被拒绝，不会伪造 clear。
- 分支状态增加受限的分类诊断：错误类别、是否适配、结束原因、文本字符数
  和输出 token 数。诊断不包含原始模型文本或图片，也不写进 AnalysisResult。

## 验证与部署

- 新提示同图、同线路重放 2/2 成功，均返回标准 `events` 数组和抽烟阳性，
  confidence 0.98，耗时分别约 1.79 秒、1.23 秒。
- 两条旧格式真实阳性都能严格适配，结果与规范包装等价。
- 完整回归：**1974 passed，6 skipped**；修改文件 Ruff 与 diff 检查通过。
- 已部署 8080：`2026.09.10-full.3-single-event-fix`。
- 部署后通过真实 8080 WebSocket 摄像头入口重发这张已授权画面：
  收到 smoking 阳性，confidence **0.98**，模型耗时 **1.763 秒**；
  证据 JPEG 的 `X-Analysis-Message-Id` 与结果 JSON 一致，图中存在红色
  SMOKING 告警和烟具框，`last_error:null`。验证结束恢复会话空闲。

这是格式兼容和告警发布验证，不是整体抽烟召回率或框精度评估。
输入为保留的 preview JPEG，可能与当时送模 JPEG 的编码略有差异。
