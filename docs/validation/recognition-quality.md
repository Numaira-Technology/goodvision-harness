## 文字观察中间层的淘汰依据（2026-09-21）

Qwen3-VL-30B 先输出人物框及短英文观察，再由 TypeSafe Jev 判断四类事件，最后经过现有严格解析器。六个四帧窗口各重复三次，比较简短 STANDARD、简短 HIGH、逐帧 HIGH 三种提示；原图只交给 Qwen，Jev 只收到文字。几何来自 Qwen，候选概率不代表校准后的视觉准确率。

三组有效请求中位延迟从直接 JSON 的 2.435 / 2.462 / 2.570 秒降到 1.897 / 1.818 / 1.692 秒；Jev 自身增加约 0.36～0.38 秒，主要收益来自描述缩短。直接 JSON 有效数为 18/18、13/18、15/18，新路径均为 18/18；失败未当成阴性。计时含消息构造、两次串行 HTTP 和解析，不含采样、跟踪或显示。

**三组文字路径的跌倒窗口均为 0/3，直接 JSON 均为 3/3。** 描述把侧倒写成可控下降或下蹲，关键视觉信息已丢失；即使 Jev 高置信也不能恢复。因此保留适配层及离线工具用于反例复核，不接入生产默认路径。该单片实验没有证明一般定位质量或识别率。

证据：[汇总](evidence/vlm-jev-20260921/summary.json)及同目录四份 manifest 保存模型、提示、配置和图像哈希。原始输出在本地 `artifacts/jev-*`；复现入口为 [vlm_jev_benchmark.py](../../tools/vlm_jev_benchmark.py)，运行方式见[工具清单](../../tools/README.md#text-observation-comparison)。

## Simple Jev 直接看图实验（2026-09-22）

本轮直接将四张原图交给 Qwen 分类，取消文字描述中间层。公共 demo 确实不需要 API key；先前把生产接口的鉴权要求套到 demo 是错误的。本次使用公共模型列表中的 `featherless-ai/Qwen3.6-35B-A3B-classifier`。文档仍写 demo 为纯文本输入，但实际接口接受四图并返回结果，灰色空白图与真实图的判断不同；这是当天部署的实测行为，不是文档承诺的稳定视觉接口。[接口文档](https://simple-jev.featherless.ai/docs)

Simple Jev 在答案位置读取候选 token 分数，再由服务端组装 JSON。它与上一轮 TypeSafe Jev 服务不同。这里为 fight、smoking、fall、weapon 各设置一道 present/absent/uncertain 三选一题；没有让模型生成描述，也没有让模型逐字生成完整 JSON。[机制说明](https://simple-jev.featherless.ai/how-it-works)

### 输入与比较范围

实验分支 `codex/vlm-jev-experiment`，基于 `cc35de9` 新增离线工具，生产流程未改动。同一 `sample-sdr.mp4`（SHA-256 与上文相同），取终点 4.0、9.6、12.8、20.0、24.0、42.4 秒的六个窗口；每窗四帧、间隔 0.4 秒，长边 720、JPEG90。吸烟 HIGH，其余 STANDARD。参考分别为吸烟样动作、挥拳、倒地过程，以及走动、主动弯腰、安静背景；吸烟参考不证明真实烟草使用，也没有武器阳性样本。

每路线六窗 × 三次重复，共 90 次正式请求，另有五次预热和一次灰图对照，总计 **96/96 成功**：Simple Jev 20 次、OpenRouter 76 次。请求串行、轮换路线顺序、无重试、复用连接。OpenRouter 的 `qwen/qwen3-vl-8b-instruct` 和 `qwen/qwen3.6-flash` 均固定 Alibaba、禁止供应商回退；Flash 关闭 reasoning。

计时包括消息准备、上传、服务端处理、响应和本地解析，排除初次视频解码、预热与灰图对照；未计入后续定位、跟踪与事件确认。完整 JSON 使用现有生产提示词和解析器；精简事件 JSON 只要求四个 true/false/null。三条事件分类路线没有人物框，组装现有格式时明确保留 `subjects=[]`、`subject_ids=[]`，不能作为完整输出的直接替代。

### 对速度与方案的判断

Simple Jev 相对 8B 完整 JSON 的中位耗时减少 42.9%，但省略了定位且漏掉两类目标动作，不能视为等价加速。与同为事件分类的 8B 比较，中位数之比看似快 16.1%；按同窗口、同一轮配对后，18 对仅 10 对更快，配对相对加速的中位数只有 **0.7%**。首轮两者中位数为 Simple Jev 2.502 秒、8B 事件 JSON 2.194 秒，后两轮 OpenRouter 耗时上升；因此不能宣称稳定领先。

同模型比较更清楚：8B 精简事件 JSON 相对完整 JSON，中位耗时下降 **31.9%**，18 对全部更快，三个目标窗口的阳性次数均保持 3/3。Flash 精简后减少 43.7%，但出现更多 unknown。本轮更支持继续验证“8B 先输出事件，人物定位另行处理”；后续定位的总成本尚未测量，不能直接承诺整个现有流程提速。

这批结果不支持把当前四题 Simple Jev 配置直接替换生产识别。它没有经过描述瓶颈，仍然漏判，说明这次问题不能只归因于文字描述丢信息。此前 320 像素、单道简短跌倒题探针曾返回 present=0.956，而 720 像素、四道生产策略题返回阴性；分辨率、提示词和题数同时不同，尚不能确定原因，也不能据此否定所有 Simple Jev 提示词。

两平台的模型、部署与提示词不同，无法隔离下一 token 分类机制本身的收益；本轮没有相同 35B 模型同服务器的普通 JSON 对照，也不能与上一日 30B/TypeSafe 的耗时直接比较。六个固定窗口重复三次不是 18 个独立场景，不能推广一般召回率、准确率或吞吐。公共 demo 是否使用缓存、硬件和排队细节未知。

## Drive 30 段视频分层复测（2026-09-22）

本轮更换素材后，Simple Jev 能识别多数吸烟和跌倒片段，不能把上一轮单一录像的漏检外推到全部视频。不过它仍未获得相对 8B 事件 JSON 的速度优势。8B 精简输出最快、目标阳性覆盖较好，同时暴露出明显的日常活动误报；目前各路线都有尚未解决的质量问题。

unknown 与未评估单独保留，不计作正确阴性；本报告投票中的 unknown 包含显式 null 和标签遗漏，证据另列遗漏数量。日常活动中，Simple Jev、8B 事件、Flash 事件、8B 完整、Flash 完整分别有 0、1、4、6、5 段包含多数 unknown；四标签明确全阴性的片段分别为 9、5、4、3、3 段。一个视频可能同时包含阳性和 unknown，因此两者数量可重叠。

### 速度与质量取舍

8B 事件 JSON 相对自己的完整 JSON，耗时中位数减少 **61.5%**，同视频、同轮次的 90 对中 89 对更快，配对耗时降幅中位数为 60.9%。Simple Jev 相对 8B 事件 JSON 的耗时中位数反而增加 **55.9%**，90 对只有 2 对更快。Simple Jev 相对 8B 完整 JSON 少用 39.9% 时间，但没有人物定位，且存在额外漏检，不能当成完整输出的等价替换。

三轮耗时中位数（秒）：Simple Jev 为 1.596 / 1.475 / 1.457，8B 事件为 1.001 / 0.875 / 0.946。这次三轮的快慢关系一致。输出 token 中位数依次为 4、22、32、230、288；Simple Jev 的 4 对应四道题的接口计数，不是传输 JSON 的实际文字长度。

具体反例均来自调用前已经固定的参考窗口：

- Simple Jev 漏掉 `v01/v02/v08` 三个跌倒片段，以及 `v21/v26` 两个吸烟片段；低光照坐沙发的 `v16` 三次都误报 weapon。该次首轮 weapon 分数为 present 0.506638、absent 0.348207、uncertain 0.145154。
- 8B 事件 JSON 在 `v11` 下蹲片段误报 smoking，在 `v13` 躺床、`v14` 低光下蹲、`v18` 手臂支撑身体下压片段误报 fall；四个误报三轮都出现。
- Flash 事件 JSON 误报 `v14/v18` 的 fall，并在 `v16` 两次误报 smoking。8B 完整 JSON 误报 `v13/v14/v18` 的 fall；Flash 完整 JSON 误报 `v18/v19` 的 fall。增加完整结构没有消除日常活动误报。

四标签判断三次完全相同的视频数依次为 30/30、29/30、29/30、23/30、30/30。稳定地重复错误不等于正确。完整 JSON 也需要单独验收定位：8B 与参考吻合的目标阳性中 55/60 有合法人物引用，Flash 为 60/60；这里只验证引用和坐标格式，未验证人物框 IoU、身份关联或跟踪。三条事件分类路线均无人物框。

本轮支持把 8B 精简事件 JSON 继续作为速度候选，但在部署前仍需解决日常活动误报和后续定位成本。当前 Simple Jev 配置的优势是本组日常活动误报较少，代价是更多目标漏检；引入这一层没有优于小模型直接生成四个事件判断的速度证据。

### 素材、固定配置与边界

来源为用户提供的 [Streaming-Harness 文件夹](https://drive.google.com/drive/folders/1zt7_9s0zNNY4aFBrzBV5HevBvnboWenq)：`hmdb51/extracted/smoke_mp4` 109 段、`ur_fall_rgb` 中 30 段跌倒和 40 段日常活动。经用户选择，本轮各取 10 段。UR 按编号分散选取；吸烟选择十个不同来源标题，覆盖文件名标示的不同视角与画质。这是目的性分层选择，不是随机抽样。

先查看整段接触表，再核对每个最终四帧窗口，固定取帧和参考后才调用模型。参考由助手结合素材类别与可见动作核对，没有独立多人标注。每段只测一个 1.2 秒窗口，没有持续扫描整段视频；跌倒窗口覆盖下降过程，日常活动窗口包含主动坐、蹲、弯腰、躺下和手臂支撑动作。没有打架或持械阳性，不能评估这两类召回率。UR 跌倒仍主要是室内演示，吸烟包含影视和近景视频，不能代表远距离多人监控。

完全复用 `3651916` 的五路线请求、提示词、解析与计时函数，基线脚本指纹、模型 ID、四题和上下文均与上一轮一致。Simple Jev 使用免鉴权公共 demo 的 `featherless-ai/Qwen3.6-35B-A3B-classifier`；OpenRouter 的 8B 和 Flash 固定 Alibaba，禁止供应商回退，Flash 关闭 reasoning。吸烟 HIGH，其余 STANDARD；四帧相隔 0.4 秒、JPEG90、最长边上限 720。素材实际宽度 300～432、高度 240，保留原尺寸、不放大。

各组交错、路线轮换、串行请求、复用连接、45 秒超时、无重试。30 × 5 × 3 = 450 次正式请求，加五次预热与一次灰图对照，共 **456/456 成功**：Simple Jev 92 次、OpenRouter 364 次。Simple Jev、两条事件 JSON 路线和 Flash 完整 JSON 均为 90/90 次覆盖四标签；8B 完整 JSON 为 87/90，v04 首轮和 v10 前两轮仅输出 fall，其他标签按未评估保留，不能算阴性。灰图对照全阴性。150 种视频/路线请求离线核对确认使用同一组原图，文件名、类别参考和标注说明未进入模型消息。

计时包含消息准备、HTTP 上传与响应、本地解析，排除初始视频解码、预热和灰图对照；没有测后续人物定位、跟踪、确认和完整显示延迟。两平台模型和部署不同，不能把差异单独归因于下一 token 分类机制。重复请求并非独立视频，公开服务的缓存与排队细节未知；低分辨率输入和服务负载也使本轮耗时不能直接与上轮录像作因果比较。

## 双请求并发：事件 JSON 与人物定位（2026-09-22）

实现来自实验快照 `54787d6`，现已并入当前代码。Harness 默认使用 `parallel`，快速事件与人物定位分别运行；`full` 仅在显式配置时启用。旧配置省略模式时也使用双路。下表记录固定窗口 API 对照；真实回放和当前调度策略见[网络与显示](network-and-display.md)。

### 无事件短输出没有获得可用的提速证据

第一版把 `no_events` 例外放在完整格式说明末尾。455 次真实调用全部成功返回，但两组条件式定位的 180 次正式请求全部输出 `no_events`，吸烟、跌倒均为 0/10 命中。其约 0.81/1.01 秒的耗时来自错误阴性，不能算有效提速。这批失败数据完整保留。

随后用原 55.8 秒授权录像的六个窗口比较两种说明方式，共 12 次调用。选择先说明条件分支、再定义完整结构的版本，恢复目标阳性。修正版重新运行全部 455 次请求：两组定位共 180 次正式请求中 `no_events` 实际采用 **0 次**。因此当前支持“短事件信息提前返回”的并发方向，**尚未实现可靠的无事件短输出收益**，不能直接替换部署。

### 方法、范围与复现

Qwen3-VL-8B，OpenRouter 固定 Alibaba、不回退、temperature=0、非流式；短输出最多 160 token，完整/条件式最多 1600。保持此前 Drive 素材、端点、四帧 0.4 秒间隔、最长边 720、JPEG90、吸烟 HIGH/其余 STANDARD；参考与文件名不发送。主工作区同步带入了 weapon 提示改进，本轮三种提示统一使用同步后的敏感度规则，故跨轮变化不能归因于单一因素。

每轮按类别交错并轮换四种执行方式（完整、条件式、事件、双路）；双路内并发，两组试次之间不重叠。每轮 450 正式请求 + 5 预热，无重试、45 秒超时；两轮与诊断合计 **922 次**，OpenRouter 回报费用 **$0.153217**。计时包含构造请求、HTTP、解析，排除初始视频解码、SAM、事件确认和显示缓冲。逐请求离线重建核验修正版 455 份 payload 指纹及各路线图像一致性。

代码回归 151 项通过；最终并发统计修正后相关 26 项再次通过，静态检查通过。新增测试覆盖慢定位不阻塞快信息、相同证据窗口、信息与显示消费者隔离、无事件严格解析及已有人物事件的阴性复查/解除。
