# 持续事件链路验证记录

日期：2026-09-12。分支：`codex/entity-event-engine`。

## 软件验证

- 完整测试：**2370 passed，4 skipped**，耗时 143.70 秒；隔离部署 `.env` 运行。
- 四项跳过分别为 Windows 缺少权限的三项符号链接测试及一项 Linux 进程组测试。
- 修改和新增 Python 文件的 Ruff 检查通过，Git 空白检查通过。
- `compose.yaml` 与 `compose.scene.yaml` 合并配置的只读校验通过。
- 本轮未启动 Docker GPU 容器，也未构建目标 Linux 镜像。

覆盖人物持续状态、证据修订和撤回、跨帧群组归属、慢模型返回后原始证据保留、
停止／重启隔离、模型错误与未知不清除事件、有界队列、旧事件不遮住新告警、
浏览器原始画面分辨率、持续证据接口、归档、SAM 协议和控制台行为。
SAM 模型 API 的软件测试使用显式测试替身；替身不能报告真实 GPU ready。

本机完整报告保存在忽略目录 `tmp/scene-active-final-20260912.xml`。

## 真实时序模型请求

使用项目已有的一段三秒本地录像：640×480、5 FPS，共 15 帧。
人物轨迹经人工查看后提供，明确使用 `recorded_tracks` 模式，未运行 SAM。

更新模型凭据后，最终验证产生两次真实 OpenRouter 时序请求：

| 项目 | 结果 |
| --- | --- |
| 请求成功／失败 | 2／0 |
| 模型输入 | 按源时间排序的多个原始画面与人物框 |
| 引擎接受证据 | 4 条；相同源帧的重复判断不会再计一次观察 |
| 模型总 token | 5306 |
| 两次模型调用耗时之和 | 5.532 秒 |
| 标注视频 | 15 帧、640×480，可解码并已查看输出画面 |
| SAM 实测 | 否 |
| 准确率评估 | 否 |

联调暴露并修复了模型将完整 JSON 包在 Markdown 代码围栏内的兼容问题。
只剥离覆盖整条响应的完整围栏；无效字段、字符串真假值、额外正文、截断响应和
没有源帧依据的人物引用仍拒绝，失败不会变成阴性证据。

本机产物位于 `tmp/scene-recording-verified-20260912/`，包括 `report.json`、
`scene.jsonl`、`tracks.jsonl`、`annotated.mp4` 与查看用预览图。原视频、人工轨迹和
模型原始输出未加入版本库。该录像验证发生在独立输出预算覆盖旧逐帧预算的最后修复前，
当次请求沿用了 1200 token 输出上限；最终代码采用 `SCENE_MAX_TOKENS` 的独立上限，
此配置传递已有回归测试。
