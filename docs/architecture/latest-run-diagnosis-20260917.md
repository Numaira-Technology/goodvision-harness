## 已确认的失败

最后保留下来的显示统计覆盖约395.53秒：2,720个不同源画面，完整／部分／观察／传播描边均为0；实际显示约6.90 FPS，摄像头回调约7.59 FPS。最后一个约5.28秒统计窗口仅2.08 FPS、回调到画面延迟P95为7.43秒。末尾统计缺失，因此不能把这个窗口的延迟当成全run分位数，或把2,720当作全run所有呈现帧。

整个run的SAM成功处理482帧，采集期约466.12秒，平均1.034 FPS，结束积压0。模型不是完全没有工作。

### 首段：真实结果年龄超出显示预算

浏览器最后成功收到轮廓元数据约在启动后55.04秒。此前已有56个SAM输出，56/56都包含人物。后端接纳到提交测点的平均耗时4.456秒、P50 4.495秒、P95约6.197秒、最大6.746秒（P95采用nearest-rank）；尚不包括浏览器采集到上传接纳以及显示端接收、解析和Worker排队。

在当前设置下，源帧的模型结果要赶上显示及有限传播，名义预算是1.7+1.5=3.2秒。56帧中51帧的后端年龄测点已经超过3.2秒，显示时序预算与实测明显不匹配。用相邻访问日志做辅助对照，seq0／37／257剩余约0.680／0.162／0.175秒；但metadata发布略早于协调器完成日志，访问日志也不记录响应内容，这些邻接值不能当作实际最早可用时间或严格覆盖率证明。

这足以证明大多数结果在首段已经太旧；现有日志不足以严格证明首个锚点为何连一个画面都未赶上。启动完成时间、逐次元数据中的最新人物源时间与目标呈现源时间未被记录，不能用猜测补齐。

首段19/19个请求与远端日志按request_id对应成功。每请求平均：最旧源的请求前等待2.632秒，准备0.444秒（包含在等待里），客户端append全段2.212秒，其中HTTP往返2.140秒；远端读取请求体1.362秒、原生SAM推进0.370秒、整个native处理0.385秒；提交队列0.126秒、提交全段0.382秒。各阶段存在包含和重叠，不能把这一列直接相加。按56个源帧加权，在实际source-age测点的分解为1.849秒请求前等待＋2.298秒append＋0.136秒提交等待＋0.173秒提交回调前半段＝4.456秒，提交日志落盘尾段不在这个测点内。

因此，首段的主要耗时是输入请求读取／往返及串行请求前排队，而非SAM原生GPU计算。现有日志不能将请求体读取耗时进一步拆成客户端发送调度、SSH通道或远端读取调度。run结束后的三次只读健康请求往返约0.319–0.329秒，仅说明空闲通道基线，不能当成该run全部网络延迟。

浏览器的拒绝分布也支持问题发生在几何传播之前：`no_anchor=1760`、`anchor_expired=768`、`not_ready=192`，各种光流／边界拒绝均为0。不能把这轮零描边解释成轮廓跟随算法把所有人体边界都拒绝了。

### 后段：轮廓元数据长期没有成功更新

累计320次请求中，162次被浏览器成功读取，156次超时，另有1次会话不匹配；最后报告的成功更新年龄为340.486秒。555个`metadata_anchors_received`是每次快照的锚点数量累计，含重复传送，并非555个不同观察。

服务访问日志中，15:10:23至15:14:19约236秒没有完成轮廓元数据响应；显示统计、状态和scene也有类似长空窗。但容器内部健康检查仍约15秒响应，摄像头WebSocket上传和SAM提交持续发生。因此尚不能判定整个后端事件循环永久死锁，也不能仅归因于GPU计算。

浏览器同源连接排队、主线程延迟、服务线程池积压仍需区分。当前检测页面已关闭，无法事后读取这一轮浏览器网络Timing。代码审查另确认部分异步路由仍同步争用锁，内存复现中持锁180毫秒可阻塞事件循环约172–188毫秒；这是需要修复的风险，但不等于已证实本次236秒空窗的根因。

## 日志缺口与下一步

显示详细统计调用了普通应用logger的INFO级别，而当前Uvicorn配置未输出该logger的INFO；本轮日志只保留16条metrics访问记录，没有各窗口的统计正文。状态接口最后一次报告无法恢复此前所有窗口。

下一步应优先处理真实链路可用性：把逐窗口统计接入已配置的结构化日志；记录元数据请求入口、处理起止、返回的最新人物源时间、服务线程池占用及浏览器收取／应用时间，区分请求未到服务与后端等待；进一步定位SAM请求发送、远端读取和顺序等待的耗时，保持已接纳帧的顺序与完整性。确认这些瓶颈后再调整调度与显示预算，不用扩大传播时间上限或放宽几何门槛掩盖延迟。验收必须让真实摄像头、SAM、Face、VLM和记录分支同时运行。

本轮仅保全证据与诊断，尚未修改产品代码或部署新镜像。昨晚的合成画面性能及SAM单分支结果不足以证明本轮完整系统达到15 FPS／低延迟要求。
