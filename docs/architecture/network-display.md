# 网络视频连续显示

网络视频与本机摄像头共用连续画面与轮廓传播机制。
显示缓冲可配置；真实场景的描边覆盖率取决于跟踪延迟、源帧率和运动估计质量。

## 共用的显示能力

- 主画面按真实采集帧连续播放，不再只播放 SAM 完成帧。分析队列、SAM 顺序推进、Face/VLM 判断规则保持独立。
- 网络视频与本机摄像头共用 `BrowserController` 和 `ContourHistory`：相邻真实帧光流、历史运动链、前后锚点校正、重定位、遮挡/出入画/过期拒绝及原有最多 0.35 秒短时近似补帧。未扩大 1.5 秒传播限制。
- 复用原图尺寸播放、按面积限制的运动工作图、Worker 预处理、轮廓预取、几何缓存和事件变化不重算几何的行为。
- 复用会话/源序号/源时间/裁剪版本隔离，以及姓名、姓名撤销、临时 ID、中文事件文字和按源时间生效的描边颜色。
- 复用浏览器真实不同源帧率、完整/近似/无轮廓比例、Worker 排队、拒绝原因、可见性和长任务统计。

## 网络路径修正

`VideoConnection` 保留唯一解码器，显示编码拥有独立消费线程，不再在采集线程中每 250 毫秒编码一次。默认保持裁剪后的源尺寸；模型输入尺寸独立。慢显示编码不阻塞采集或分析，未编码显示帧计入日志。

同源 `/v1/video/display/frames` 以有界二进制批次传送 JPEG 原图、真实源标识、共用显示配置和 metadata 增量。单次最多 8 帧 / 8 MiB；慢观察者落后超过 0.5 秒时明确跳过旧显示积压，源时间缺口交给既有传播校验，不能将其计成分析丢帧。多路网关新增同源转发；本路直接取显示数据，避免自代理开销。视频卡片使用各自独立的显示控制器。停止分析后仍保留连接预览，并清除旧 run 的轮廓。

原 `annotated/latest.jpg` 继续作为精确源帧标注导出及兼容入口，不承担新浏览器主显示。源 metadata 在网络采集回调绑定，不再依赖本机摄像头上传 ACK 才建立身份。


## 诊断日志



`network_receive_timing` 每约 5 秒汇总一次，断开时补最终记录。所有数据以
`connection_id` 关联显示编码日志；`recent_frames.source_sequence` 对应实际显示和分析源帧。

- WebRTC 入站视频 RTP：每路 SSRC 的累计收包、累计丢包、相邻统计增量、RTP jitter 原始刻度；
  协商视频时钟唯一时再换算为秒。丢包计数增量可以因迟到包补回而为负，不截成零。
- DTLS transport 收发包数和字节数，包括传输层其他流量，不能当作纯视频码率。
- 解码后帧数与间隔、超过 200 毫秒的次数、等待超过 500 毫秒的次数。
- 解码帧 PTS、关键帧及 PyAV `is_corrupt` 标记；每窗仅保留最近 8 条帧元数据，无图像内容。
- `receiver_pts_delay_growth_seconds` 是接收时钟相对源 PTS 的延迟增长量，
  从首次可用 PTS 起算；不是摄像头曝光至显示的绝对延迟。PTS 回退/重复单独计数并重置比较基点。
- `rate_limit_skipped_frames` 是原有输出帧率限制主动跳过；
  `handoff_queue_dropped_frames` 是已解码帧在有界交接队列被覆盖。两者都不是 RTP 丢包。
- `receive_wait` 是等待解码后帧可取的总时间，包含网络等待、解码及调度，不能标成纯解码 CPU 耗时。
- `color_conversion` 是解码帧转 BGR 的耗时；`handoff_queue_wait` 是交接至采集消费者的等待；
  `stats_loop_lag` 是 WebRTC 事件循环统计定时器的延误。

现有 aiortc 1.15.0 的公开入站统计不提供 NACK/PLI 数量，日志明确标为不可用；
不通过修改私有接收逻辑收集这些指标。`is_corrupt=false` 也不能证明画面没有压缩噪点或隐蔽损坏。

`network_capture_display_timing` 在原日志上增加显示编码排队平均/最大耗时、JPEG 字节数、
JPEG 质量参数和编码错误累计值；编码异常最多每 5 秒记录一次 `network_display_encode_error`，
只输出异常类型，不输出可能带地址的异常正文。

`network_display_delivery_timing` 汇总响应数、空响应数、帧数、字节数、响应准备耗时以及
所取 JPEG 自编码完成后等待的最大时间。同一窗口涉及的会话 ID 列在 `stream_session_ids`，
不把跨开始/停止边界的汇总冒充成单一 run。这个事件只测响应准备，不代表套接字发送完成；
实际下载与浏览器解码耗时继续看 `network_video_display_timing`。

## 负载与边界

每个阶段最多保留 128 个耗时样本，报告均值、最大值及最近样本的 P95；
每连接每 5 秒查询一次进程内 `getStats()`，不创建第二路视频连接。
没有输出视频地址、鉴权信息、完整 SDP、身份标签或图像数据。

日志可以帮助区分上游收包异常、接收/解码出帧稀疏、源时间积压、限帧、队列覆盖、
转图、JPEG 编码和浏览器下载。单靠数值日志仍不能代替瞬时花屏的图像对照。
