## UI 接线证据

从正在运行的容器复制了 dashboard、service、scene worker、scene model。部署 dashboard 与工作区文件 SHA256 相同：`0AF8E0CF05244A0F116158224BC316F022A4C23A210FE2F0CE384D125EAC7A54`。

- `service.py` 的 `frame_features` 在 scene active 模式下只保留 stranger；四类行为由持续事件引擎分析。
- `_on_scene_update()` 发布到 `scene_results`，不发布成逐帧 `AnalysisResult`。
- dashboard 的 `connectResultEvents()` 只监听 `analysis_result`；`log()` 据此追加 Live result log。
- `log()` 又拿全局勾选的五类能力减去此条人脸结果包含的类别，于是逐行显示四类行为“Not analyzed in this frame”。它没有说明这些行为正在另一条连续观察通道中分析。
- 持续事件结果由 `/v1/scene` 的轮询交给 `renderScene()` / `renderSceneDecision()`，进入连续事件判断和人物事件面板，没有进入 Live result log。

因此这是日志范围和文案与当前架构不一致，并非已识别的吸烟被后端丢弃。仅检查 API 和代码无法还原浏览器在每个时刻实际绘制的内容。

## 修复方向

1. 明确区分人脸逐帧日志与持续行为事件，并把持续事件确认、更新、结束及复核失败接入可见日志；不要把人脸结果缺少行为字段描述成整个系统没有分析。
2. 暴露 VLM 成功/失败次数和分析进度，分别追踪响应体超时与积压。不能仅放宽超时时限就宣称实时性恢复。
